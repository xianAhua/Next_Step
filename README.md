# 航向 · 就业准备工作台

> 把研究方向变成项目，把项目变成可展示的能力。

航向是一个面向控制工程、无人机与机器人相关方向学生的个人就业准备工具。它把学习路线、技能积累、项目实践、岗位跟踪和每周复盘放在同一个页面里，帮助你明确下一步行动，并持续留下代码、实验和文档等能力证据。

当前版本以**控制与状态估计**为起步主线，默认目标城市为**广州 / 深圳**。方向、城市、计划起点和每周投入时长都可以在设置中调整。

项目使用原生 HTML、CSS 和 JavaScript 编写。页面样式与交互脚本集中在一个 HTML 文件中，无需安装依赖或配置后端。

## 功能介绍

| 模块 | 主要功能 |
| --- | --- |
| 成长总览 | 查看本周任务、计划完成度、已完成项目数量，以及达到项目级别的自评技能数量 |
| 12 周路线 | 内置 36 项建议任务；支持新增、编辑、删除、勾选完成，以及按完成状态筛选 |
| 技能自评 | 对 8 类能力进行分级自评，并记录代码、实验、笔记或演示链接等证据 |
| 项目仓库 | 记录项目问题、当前状态、成果、实验结果与局限，关联代码或文档链接 |
| 求职跟踪 | 记录公司、岗位、城市、职位链接、求职阶段、跟进日期和岗位要求 |
| 复盘笔记 | 按日期记录阶段成果、遇到的卡点、留下的证据和下一步行动 |

此外，还支持：

- **全局搜索**：查找任务、技能、项目、岗位和复盘记录。
- **自动保存**：在浏览器允许本地存储时，自动保存页面中的更改。
- **备份与恢复**：导出 JSON 备份，并在另一个浏览器或设备中导入。
- **响应式布局**：提供桌面布局与窄屏导航样式，适应不同屏幕尺寸。

## 内置学习路线

12 周路线是一份可以调整的起步模板。默认每周投入 10 小时，先建立实验基线，再形成项目成果，最后用真实岗位要求校准方向。

| 阶段 | 重点内容 | 建议产出 |
| --- | --- | --- |
| 第 1–4 周 | C++ 与工程基础、状态空间模型、PID 与 LQR | 可运行的小程序、模型说明和控制对比实验 |
| 第 5–8 周 | PX4 仿真、KF / EKF、扰动与观测缺失实验 | 仿真日志、估计误差曲线、鲁棒性对比结果 |
| 第 9–12 周 | ROS 2 数据流、项目整理、岗位分析和面试复盘 | 可复现的项目文档、演示、岗位匹配分析和下一轮计划 |

每周都包含具体任务与验收成果。可以按导师项目、课程安排和实际进度修改任务。

调整计划起点时，尚未手动编辑的模板任务日期会同步平移；自建或手动编辑后的任务保留指定日期。每周投入时长用于标记时间预算，修改它不会自动重新分配任务。

## 技能与项目

技能自评覆盖 C++、Linux / Git / 构建、线性代数与状态空间、控制算法、状态估计与融合、PX4 / 仿真 / 日志、ROS 2，以及 Python / MATLAB 实验。

| 等级 | 含义 |
| --- | --- |
| 0 | 待自评 |
| 1 | 了解概念 |
| 2 | 能做练习 |
| 3 | 能做项目 |
| 4 | 可讲清原理 |

初始技能均为“待自评”。等级由使用者自行选择，建议结合实际成果填写证据。

项目仓库预置了三个候选草案：

1. **轨迹跟踪控制对比**：在相同模型、轨迹和扰动条件下，比较 PID 与 LQR 的表现。
2. **多传感器状态估计**：验证 KF / EKF 在噪声、观测缺失和初始化偏差下的效果。
3. **仿真与日志分析链路**：整理从仿真运行、参数配置到日志提取、结果分析的完整流程。

这些草案用于帮助起步，初始状态均为“项目草案”。建议先选一个问题做完整，再扩展其他项目。

求职模块初始为空，需要自行添加真实职位。支持的阶段为：待研究、准备投递、已投递、面试中、已录用、已结束。跟进日期用于页面展示和统计，目前没有后台提醒功能。

## 开始使用

1. 下载项目文件，用现代浏览器打开 `index.html`。
2. 在设置中确认主线方向、目标城市、计划起点和每周时间预算。
3. 查看当前周任务，按自己的课业与项目安排进行调整。
4. 完成任务后勾选，并把代码、实验结果或文档记入技能证据和项目记录。
5. 每周写一次复盘，定期导出备份。

`航向就业准备工作台_可用版.html` 也可以独立打开。当前它与 `index.html` 内容一致，日常使用固定其中一个入口即可。

## 数据保存与备份

个人设置、任务、技能自评、项目、岗位和复盘记录保存在当前浏览器的 `localStorage` 中。应用没有用于同步这些记录的后端接口。

- **上传 GitHub 的是页面代码**，浏览器里的进度不会随代码提交自动上传。
- 不同设备、浏览器或页面地址中的数据可能相互独立；本地文件与 GitHub Pages 网页之间也需要手动迁移进度。
- 更换使用环境前，点击侧栏的“导出备份”，保存 JSON 文件；在新环境点击“恢复备份”并选择该文件。
- 恢复备份会覆盖当前记录，页面会先展示备份内容摘要并要求确认。
- 当前导入文件大小上限为 5 MB，导入时会检查备份版本与数据格式。
- 清除浏览器站点数据可能导致进度丢失；如果浏览器无法保存，页面会提示先导出备份。

## 发布到 GitHub Pages

如果希望通过网址打开工作台，可以将 `index.html` 和这份 `README.md` 放在 GitHub 仓库根目录，再进入仓库的 **Settings → Pages** 设置发布来源：

| 设置项 | 值 |
| --- | --- |
| Source | Deploy from a branch |
| Branch | main（或实际存放页面的分支） |
| Folder | / (root) |

保存后，等待部署完成，在 Pages 页面点击 **Visit site** 打开网站。

GitHub Free 使用 GitHub Pages 发布此类个人项目时，需要使用公开仓库。公开仓库中的页面源码会对外可见；部署网页后，个人使用记录仍保存在各自的浏览器中。

配置细节可参考 [GitHub Pages 官方文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 文件说明

| 文件 | 用途 |
